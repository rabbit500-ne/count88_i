# 設計根本方針
ここでは **「FastAPI + Jinja + htmx を今すぐ使い、将来 React 等に置き換えても API を壊さない」**ことを明確な設計目標として、

* 破綻しにくい境界定義
* htmx と JSON API の不整合を根本から解消
* 本番前提（CSRF・エラー・拡張性）

をすべて満たす **最小だが実務耐性のある構成**を目指す。


# 全体方針（結論）

**UI と API を「URL 空間」で明確に分離し、Usecase 層を唯一の実行主体にする**

```
Browser (htmx) ──> /ui/* ─┐
                           ├─> Usecase ─> Domain ─> Repository
External Client ─> /api/* ─┘
```

* htmx は **HTMLフラグメント専用**
* API は **JSON 専用**
* Domain / Usecase は完全共有
* 表現（HTML / JSON）は Controller の責務

これにより

* htmx と JSON の混線が起きない
* フロントを React に差し替えても API が無傷
* テスト・責務分離・拡張がすべて素直

になります。

* **ビジネスロジックは usecase 以外に置かない**


# Domain（純粋・不変）

## 一言で
**Domain =「業務ルール（何が正しいか）」**を表すコード。

## ここに置くもの / 置かないもの（判断基準）
置くもの：

* **不変条件**（例：完了済みは二重完了できない）
* **状態遷移**（例：未完了→完了）
* **業務としての計算・判定**（例：期限切れ判定、料金計算など）

置かないもの：

* HTTP / FastAPI / Request / Response
* DB・ORM・SQL・外部API呼び出し
* HTML / JSON の整形（＝表現）

### 迷ったときの質問
* 「このルールは UI を React に変えても、DB を Postgres に変えても同じか？」→ **Yes なら Domain**
* 「それは“業務として正しい/間違い”を決めているか？」→ **Yes なら Domain**

```python
# domain/task.py
from dataclasses import dataclass

@dataclass
class Task:
    id: str
    completed: bool = False

    def complete(self):
        if self.completed:
            raise ValueError("already completed")
        self.completed = True
```

* FastAPI 非依存
* HTML / JSON 非依存
* テスト最優先


# Usecase（核心）

## 一言で
**Usecase =「ユーザーの操作を成立させる手順（どう進めるか）」**を表すコード。

## ここに置くもの / 置かないもの（判断基準）
置くもの：

* Repository 経由で **取得→Domainの操作→保存** を並べる（オーケストレーション）
* **トランザクション境界**や一連の処理単位（※実DB化しても守れる形）
* UI/API の差を吸収する「実行の中心」

置かないもの：

* HTML / JSON の生成（＝Controllerの責務）
* htmx の `hx-*` やテンプレート都合
* FastAPI の Request 依存（入力は基本プリミティブで受ける）

### 迷ったときの質問
* 「“誰が・何をしたい”という操作を1つ成立させる流れか？」→ **Yes なら Usecase**
* 「Domain のメソッドを複数呼び、保存や通知なども絡むか？」→ **Yes なら Usecase**

```python
# usecase/task_usecase.py
from domain.task import Task

class TaskUsecase:
    def __init__(self, repo):
        self.repo = repo

    def complete_task(self, task_id: str) -> Task:
        task = self.repo.get(task_id)
        task.complete()
        self.repo.save(task)
        return task
```

**ここが唯一「処理を実行してよい場所」**
UI / API は必ずこれを呼ぶ。


# Repository（Infrastructure）

```python
# infra/task_repository.py
from domain.task import Task

class TaskRepository:
    def __init__(self):
        self._db = {}

    def get(self, task_id: str) -> Task:
        return self._db[task_id]

    def save(self, task: Task):
        self._db[task.id] = task
```

* 実DB差し替え可
* テスト時は in-memory でOK


# DI（FastAPI 依存性注入）

```python
# deps.py
from infra.task_repository import TaskRepository
from usecase.task_usecase import TaskUsecase

repo = TaskRepository()

def get_task_usecase():
    return TaskUsecase(repo)
```


# UI（htmx / HTML 専用）

## Router

```python
# ui/router.py
from fastapi import APIRouter, Depends, Request
from fastapi.responses import HTMLResponse
from deps import get_task_usecase
from ui.csrf import verify_csrf

router = APIRouter(prefix="/ui")

@router.post("/tasks/{task_id}/complete", response_class=HTMLResponse)
def complete_task(
    task_id: str,
    request: Request,
    usecase = Depends(get_task_usecase),
):
    verify_csrf(request)
    task = usecase.complete_task(task_id)
    return render_partial("_task_row.html", {"task": task})
```

### ポイント

* **HTMLしか返さない**
* htmx の `hx-swap` 前提
* CSRF は UI 層で完結


# API（JSON 専用）

```python
# api/router.py
from fastapi import APIRouter, Depends
from deps import get_task_usecase
from api.schemas import TaskResponse

router = APIRouter(prefix="/api")

@router.post("/tasks/{task_id}/complete", response_model=TaskResponse)
def complete_task(
    task_id: str,
    usecase = Depends(get_task_usecase),
):
    task = usecase.complete_task(task_id)
    return TaskResponse.from_domain(task)
```

```python
# api/schemas.py
from pydantic import BaseModel

class TaskResponse(BaseModel):
    id: str
    completed: bool

    @classmethod
    def from_domain(cls, task):
        return cls(id=task.id, completed=task.completed)
```

# CSRF（最低限・実務OK）

```python
# ui/csrf.py
from fastapi import Request, HTTPException

def verify_csrf(request: Request):
    token = request.headers.get("X-CSRF-Token")
    if token != request.session.get("csrf"):
        raise HTTPException(403)
```

* htmx はヘッダ注入が容易
* Cookie + header の組み合わせが安全

# htmx 側（HTML）

```html
<button
  hx-post="/ui/tasks/{{ task.id }}/complete"
  hx-target="#task-{{ task.id }}"
  hx-swap="outerHTML"
  hx-headers='{"X-CSRF-Token": "{{ csrf }}"}'>
  Complete
</button>
```

# この構成で解決できること

| 問題              | 解決                        |
| --------------- | ------------------------- |
| htmx と JSON の混線 | URL レベルで完全分離              |
| ロジック散乱          | Usecase に一極集中             |
| 将来 React 移行     | `/api/*` をそのまま利用          |
| CSRF            | UI 層で閉じる                  |
| テスト             | Domain / Usecase を単体テスト可能 |
| 仕様変更            | 表現を壊さず進化                  |

# 記事との決定的な違い（重要）

* 「API 層がロジックを持たない」を**実装で保証**
* htmx を **HTML BFF として割り切る**
* 「最小構成」でも **壊れ方が予測可能**

# テスト方針
テストコードは
仕様テスト、コードテストに分ける。
仕様テストは、仕様に基づいたテストコード。
コードテストは、仕様テストの実装上の抜けを補う、テストカバレッジを高めるためのテストコード。
