# 冒頭
タイトル。段落にしない

# 段落
段落は作成してもよいが、
階層が無駄に深くなるのを防ぐため、不必要に段落は作らない。
例えば仕様書の場合は 「# 仕様」などとしない。あたり前なので。

# 目次
目次は作らない

# 水平線
水平線は作らない。

# ドキュメントタイプ
## 企画書
プロジェクトの背景・目的・目標・スコープを記述する。
またドキュメントの目録を記述する。
プロジェクトの起点となるドキュメント。

## エンドユーザ仕様書
エンドユーザ視点での仕様（ふるまい）を記述する。
UI/UX または API。

## 内部仕様書
各モジュールの仕様を記述する。
< 本ドキュメントの目的 >
api-server, task-server, infra の各モジュールの仕様を記述し、それらがどのように連携し、目的を達成するか。
また、各モジュールの責務を記述する。
また、各モジュールの開発者が他のモジュールの設計・コードを読まずに開発を進められるようにする。
例えば、api-server モジュール開発では task-server の内部はどうでもいいが、task-serverの仕様は影響をうける。

## 各モジュールの設計書
api-server設計書、task-server設計書、infra設計書を作成する。
* なぜその設計にしたのか。
* プログラムを読む上で助けとなる説明を記述する。
* クラス図などは基本不要。
